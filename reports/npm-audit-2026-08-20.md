# The npm install surface, audited 2026-08-20

The semantic layer (CP-9) is the only thing in this repository that is not
Python, and it arrived as one line — `npm install @xenova/transformers` —
which pulled in **68 packages and 252 MB** that nobody had looked at since.
`node_modules/` is gitignored; `package.json` and `package-lock.json` are
tracked, so the lockfile is the only part under review, and it never has been.

This is the audit. Every number below was measured on this machine with
node 20.20.2 and npm 10.8.2, not read off a README.

Licences: 45 MIT, 13 Apache-2.0, 12 BSD-3-Clause, 7 ISC, one `(MIT OR WTFPL)`,

## `npm ci` is reproducible, and that is worth saying

    npm ci --ignore-scripts   →  80 packages in 1.7 s

Every entry carries an `integrity` hash, so a fresh install is byte-identical
to this one. The README's `npm install` line is therefore honest.

## Five advisories, and only one of them is on our path

`npm audit`: **1 critical, 4 high, 0 moderate, 0 low.**

| package | severity | on our execution path? |
|---|---|---|
| `protobufjs` ≤ 7.6.2 | **critical** — 11 advisories incl. arbitrary code execution | **no** |
| `onnx-proto` | high (via protobufjs) | **no** |
| `onnxruntime-web` ≤ 1.16 | high | loaded, not used |
| `sharp` < 0.35 | high — 4 libvips CVEs | **loaded** |
| `@xenova/transformers` | high (aggregate of the above) | — |

That "on our execution path" column is measured, not assumed. Loading the
model the way `embed_worker.mjs` does and then reading `require.cache`:

    loaded: color color-convert color-name color-string detect-libc
            is-arrayish long onnxruntime-common onnxruntime-node
            onnxruntime-web semver sharp simple-swizzle
    protobufjs   not loaded
    onnx-proto   not loaded

**The critical advisory never loads.** `protobufjs` reaches us through
`onnx-proto`, which is `onnxruntime-web`'s protobuf reader, and the web
backend is imported but never asked to parse anything — `onnxruntime-node`
serves every inference on this platform. Thirteen top-level packages load out
of 68.

## `sharp` is 17 MB of image processing we never use, and it is the one that loads

`sharp` is a hard dependency of `@xenova/transformers` (`^0.32.0`, not
optional), used for image *input*. This repository embeds text: `embed.py`
reads `sha256, text` from `content` and hands the worker a JSON string.
There is no path from any command here to an image.

It is also the one package with a real install-time network fetch: its
`install` script downloads a prebuilt **libvips 8.14.5** (16 MB in
`vendor/8.14.5/linux-x64/`) from a GitHub releases URL that is **not in the
lockfile**. The download is sha512-verified against hashes in `sharp`'s own
`package.json`, so it is not unchecked — but `npm ci --ignore-scripts` gives an
install where `require('sharp')` throws, which is worth knowing before someone
puts `--ignore-scripts` in a CI file and reads the failure as a fallow bug.

**Measured**: stub `sharp` out with a module that throws, and the pipeline
loads and produces a **bit-identical 384-dimension vector** — max elementwise
difference 0.0 against the real install. Confirmed twice, once by deleting the
package and once through a proper `overrides` entry:

```json
{ "overrides": { "sharp": "file:contrib/sharp-stub" } }
```

That install is **15 directories instead of 68, 229 MB instead of 252**, no
libvips download, and the same vectors.

## What is recommended, and what is not

**Not recommended: upgrading.** `@xenova/transformers` is superseded upstream
by `@huggingface/transformers` v3, which is a different package name and a
different ONNX runtime major. That is a CP-9 re-measurement (M-3 load time,
CP-9E's 12/21 paraphrase and 7/21 cross-language numbers), not a patch, and
nothing here is exploitable as it stands: no untrusted image ever reaches
`sharp`, and the critical advisory does not load.

**Recommended, and cheap:** the `sharp` override. It removes the only
advisory on the execution path, the only unlisted network fetch, and 53
directories, and it is provably behaviour-preserving on the one thing this
repository asks the library to do. The stub must *throw* rather than return
undefined — a silent no-op would turn "someone added image input" into a wrong
answer instead of an error.

**Left alone deliberately:** `onnxruntime-web`'s 66 MB. It is imported
unconditionally by the library's own backend module, so removing it is a patch
to upstream rather than a configuration change.

## The gap this audit found in our own gates

None of the 25 test modules reads `package-lock.json`. A dependency could be
added, a licence could change, an install script could appear, and every gate
in this repository would stay green — the same shape of hole as the empty
project layers CP-7B R8 was written for, one ecosystem over.
