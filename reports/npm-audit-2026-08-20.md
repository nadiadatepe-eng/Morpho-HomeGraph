# The npm install surface, audited 2026-08-20

The semantic layer (CP-9) is the only thing in this repository that is not
Python, and it arrived as one line — `npm install @xenova/transformers` —
which pulled in **68 packages and 252 MB** that nobody had looked at since.
`node_modules/` is gitignored; `package.json` and `package-lock.json` are
tracked, so the lockfile is the only part under review, and it never has been.

This is the audit. Every number below was measured on this machine with
node 20.20.2 and npm 10.8.2, not read off a README.

## What is actually there

Measured **before** the override was adopted, and left that way on purpose:
this table is the thing the decision was taken against, and rewriting it to
today's tree would delete the evidence. The tree since 2026-08-20 is **26
lockfile entries, 15 directories, 229 MB, one install script** — see *ADOPTED*
below.

| | |
|---|---|
| declared dependencies | **1** (`@xenova/transformers ^2.17.2`) |
| lockfile entries | **80** |
| directories in `node_modules` | 68 |
| on disk | 252 MB |
| `lockfileVersion` | 3 |
| entries with no `integrity` hash | **0** |
| packages with install scripts | **2** (`sharp`, `protobufjs`) |
| deprecated | 1 (`prebuild-install`, `sharp`'s downloader) |

Licences: 45 MIT, 13 Apache-2.0, 12 BSD-3-Clause, 7 ISC, one `(MIT OR WTFPL)`,
one `(BSD-2-Clause OR MIT OR Apache-2.0)`, and one `SEE LICENSE IN LICENSE.txt`
(`flatbuffers` 1.12.0, which is in fact Apache-2.0). **Nothing copyleft, nothing
unlicensed** — the `NOTICE` obligation this repository already carries for
morpho is not joined by a second one.

Four packages are 92 % of the weight: `onnxruntime-node` 92 MB,
`onnxruntime-web` 66 MB, `@xenova` 45 MB, `protobufjs` 22 MB, `sharp` 17 MB.

## `npm ci` is reproducible, and that is worth saying

    npm ci --ignore-scripts   →  80 packages in 1.7 s

Every entry carries an `integrity` hash, so a fresh install is byte-identical
to this one. The README's `npm install` line is therefore honest.

## Five advisories, and only one of them is on our path

`npm audit`: **1 critical, 4 high, 0 moderate, 0 low.**

| package | severity | on our execution path? |
|---|---|---|
| `protobufjs` ≤ 7.6.2 | **critical** — 11 advisories incl. arbitrary code execution | **no** |
| `onnx-proto` | high (via protobufjs) | **no** |
| `onnxruntime-web` ≤ 1.16 | high | loaded, not used |
| `sharp` < 0.35 | high — 4 libvips CVEs | **loaded** |
| `@xenova/transformers` | high (aggregate of the above) | — |

That "on our execution path" column is measured, not assumed. Loading the
model the way `embed_worker.mjs` does and then reading `require.cache`:

    loaded: color color-convert color-name color-string detect-libc
            is-arrayish long onnxruntime-common onnxruntime-node
            onnxruntime-web semver sharp simple-swizzle
    protobufjs   not loaded
    onnx-proto   not loaded

**The critical advisory never loads.** `protobufjs` reaches us through
`onnx-proto`, which is `onnxruntime-web`'s protobuf reader, and the web
backend is imported but never asked to parse anything — `onnxruntime-node`
serves every inference on this platform. Thirteen top-level packages load out
of 68.

## `sharp` is 17 MB of image processing we never use, and it is the one that loads

`sharp` is a hard dependency of `@xenova/transformers` (`^0.32.0`, not
optional), used for image *input*. This repository embeds text: `embed.py`
reads `sha256, text` from `content` and hands the worker a JSON string.
There is no path from any command here to an image.

It is also the one package with a real install-time network fetch: its
`install` script downloads a prebuilt **libvips 8.14.5** (16 MB in
`vendor/8.14.5/linux-x64/`) from a GitHub releases URL that is **not in the
lockfile**. The download is sha512-verified against hashes in `sharp`'s own
`package.json`, so it is not unchecked — but `npm ci --ignore-scripts` gives an
install where `require('sharp')` throws, which is worth knowing before someone
puts `--ignore-scripts` in a CI file and reads the failure as a fallow bug.

**Measured**: stub `sharp` out with a module that throws, and the pipeline
loads and produces a **bit-identical 384-dimension vector** — max elementwise
difference 0.0 against the real install.

**Re-measured independently the same day, because a recommendation resting on
one measurement rests on nothing.** The first run used one English sentence in
the working tree. The second built a fresh tree from the lockfile
(`npm ci --ignore-scripts`), wrote a *different* stub, and compared **four**
inputs — English, Norwegian, a third sentence, and the empty string, since an
empty input takes a different path through the tokenizer. All four came back
`identical=True`, worst elementwise difference **0.0**. The module cache in
that tree also confirms the loaded set independently: `protobufjs` absent in
both the real and the stubbed tree.

One input can pass by luck; four across two trees and two stubs cannot.

Confirmed by three routes in total — deleting the package, a proper
`overrides` entry, and a fresh lockfile install.

**ADOPTED 2026-08-20**, after the owner approved it. The live tree is **15
directories instead of 68, 229 MB instead of 252**, no libvips download, and
the probe re-run against the pre-override baseline gives sha256
`07105d3c…4daf0c3` — **an exact match, worst elementwise difference 0.0**.

### The spelling of the override is load-bearing

```json
{ "overrides": { "sharp": "file:../../../contrib/sharp-stub" } }
```

npm resolves a `file:` override relative to the **dependent**, not the project
root. Measured, in a throwaway clone:

| spelling | result |
|---|---|
| `file:contrib/sharp-stub` | `sharp -> @xenova/transformers/contrib/sharp-stub` — **broken** |
| `file:../../contrib/sharp-stub` | `sharp -> contrib/sharp-stub` — **broken** |
| `file:../../../contrib/sharp-stub` | `sharp -> ../contrib/sharp-stub` — **resolves** |
| absolute `file:/…/contrib/sharp-stub` | resolves, but names a real home path |

**Every broken spelling installs with `rc=0`.** The failure is silent until the
model loads, and then it is `ERR_MODULE_NOT_FOUND` from
`@xenova/transformers/src/utils/image.js`. A green `npm install` proves nothing
here; only `test -e node_modules/sharp` does, which is why gate 2d checks the
filesystem and 2c pins the exact string.

The absolute path also works and was what the handoff plan called for, but it
would write a real home directory into a published file, which CP-PUB forbids.
Three levels up resolves and is portable, so the conflict does not arise.

### The gates it moved

Six of eight went red, which is the ratchet working. Gates 2 and 2b were
re-baselined (80 → 26 entries, new name set) with the reason in the commit
message. Gates 3, 4, 5 and 6 now exempt the linked override **by name**: a
`link: true` entry is a different kind of thing from a fetched package — no
registry, no integrity, no licence on the link itself — and widening the
allowlists instead would also excuse a real unhashed dependency. Gate 6's
denominator is "all but the links", not a smaller constant a second unlicensed
package could clear. Three new checks were added (2b-src, 2c, 2d) and four
rotted needles re-pointed, plus two new ones aimed at the override itself:
un-declaring it, and respelling it the way that silently breaks.

## What is recommended, and what is not

**Not recommended: upgrading.** `@xenova/transformers` is superseded upstream
by `@huggingface/transformers` v3, which is a different package name and a
different ONNX runtime major. That is a CP-9 re-measurement (M-3 load time,
CP-9E's 12/21 paraphrase and 7/21 cross-language numbers), not a patch, and
nothing here is exploitable as it stands: no untrusted image ever reaches
`sharp`, and the critical advisory does not load.

**Adopted 2026-08-20:** the `sharp` override. It removes the only advisory on
the execution path, the only unlisted network fetch, and 53 directories, and it
is provably behaviour-preserving on the one thing this repository asks the
library to do. The stub *throws* rather than returning undefined — a silent
no-op would turn "someone added image input" into a wrong answer instead of an
error.

**Left alone deliberately:** `onnxruntime-web`'s 66 MB. It is imported
unconditionally by the library's own backend module, so removing it is a patch
to upstream rather than a configuration change.

## The gap this audit found in our own gates

None of the 25 test modules reads `package-lock.json`. A dependency could be
added, a licence could change, an install script could appear, and every gate
in this repository would stay green — the same shape of hole as the empty
project layers CP-7B R8 was written for, one ecosystem over.

**And the first version of the gate that closed it had the same shape of hole
one level down.** An independent recheck swapped one package for
`evil-typosquat`, leaving the count at 80, the licence permissive and the
integrity field well-formed. **All seven gates stayed green.** A count answers
*did the tree grow*; it never answers *is it the same tree* — and the supply-
chain change that matters most is exactly the one that keeps the total steady.

Gate 2b now pins the **set of package names**, written out rather than derived,
and the swap is a needle in the harness so it cannot rot back.
